# MEM-0004: recall FTS5(trigram) + graph_edges 하이브리드 검색

## Summary
recall과 memory capsule 검색을 LIKE 부분일치에서 FTS5(trigram)+bm25 랭킹으로 강화하고, 매칭된 항목을 시드로 graph_edges를 bounded 순회해 related 필드로 노출한다.

## Claims
- **DECISION** recall.ts와 memory.ts의 findMemoryCapsules가 3글자 이상 검색어는 decisions_fts/traces_fts/memory_fts(trigram)+bm25로, 3글자 미만은 기존 LIKE로 병합 검색하고, 매칭 id를 시드로 graph_edges를 depth 파라미터(기본 1, 최대 4)만큼 순회해 related 필드로 노출한다. (sources: DEC-0072, DEC-0074, DEC-0075)
- **CONSTRAINT** FTS5 trigram 토크나이저는 3글자 미만 쿼리를 매칭하지 못해 2글자 한글 토큰 보존 결정과 충돌하므로 LIKE fallback을 폐기하지 않았다. 그래프 확장은 graph.ts의 기존 MAX_DEPTH(4)/MAX_NODES/MAX_EDGES 상한을 그대로 재사용해 범용 그래프 쿼리를 만들지 않았다. (sources: DEC-0075, DEC-0074)
- **IMPLEMENTATION** store.ts에 3개 FTS5(trigram) 가상 테이블 추가, rebuild.ts의 기존 bulk insert 단계에서 채우고 GRAPH_PROJECTION_VERSION을 올려 기존 캐시를 자동 재생성시킴. graph.ts의 BFS를 다중 seed를 받는 expandGraph로 일반화해 showGraph와 recall이 공유. cli.ts/commands에 recall --depth 옵션 추가. RecallResult에 related 필드를 추가로만 확장(기존 필드 형태 불변). (sources: IMPL-0029)
- **VALIDATION** typecheck, build, lint, 단위 테스트 161개, e2e 테스트 33개 통과. 실제 리포지토리 .decision 데이터에 대해 sduck recall을 --depth 0/2/99(에러)로 수동 실행해 캐시 자동 재구축과 related 출력, depth 검증 오류 메시지를 확인함. (sources: EVAL-0012)
