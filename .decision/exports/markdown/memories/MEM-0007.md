# MEM-0007: 프로젝트별 고정 결정 카테고리 분류 체계 인프라

## Summary
policy.json에 프로젝트별 고정 대분류 목록(categories)을 저장하고, Decision.category가 그 목록 안의 값만 허용되도록 submit 시점에 검증한다. sduck categories suggest/set/list 명령을 추가했다. 카파시의 LLM Wiki 패턴(전체 목차를 컨텍스트에 넣고 에이전트가 직접 골라 읽기)을 적용하려면 결정들이 소수의 고정 대분류로 미리 묶여 있어야 한다는 게 동기다.

## Claims
- **DECISION** DecisionWorkspacePolicy에 categories?: string[]를 추가(기존 wiki 필드와 동일한 strict validation + atomic durable write + 동시성 락 패턴 재사용). Decision.category?: string을 추가하고, submitDraft에서 category가 있으면 정책의 categories 목록 안에 있는지 검사해 없으면(또는 taxonomy 자체가 미설정이면) DRAFT_CATEGORY_INVALID로 거부한다. category 없이 제출하면 그냥 미분류로 남아 기존 결정들과 호환된다. (sources: DEC-0087, DEC-0088)
- **CONSTRAINT** 분류 체계(categories 목록)는 소분류 없이 1단계만 지원한다(사용자가 명시적으로 선택). 카테고리별 전체 결정 목록 조회(browse) 기능과 기존 ~300개 결정의 소급 분류는 이번 범위에 없다 -- list 명령은 개수만 보여준다. sduck categories set 실행 전에 그 선택 이유를 결정으로 먼저 기록해야 한다는 건 CLI 도움말/관례로만 안내하며 기술적으로 강제하지 않는다(sduck remember/close와 같은 패턴). (sources: DEC-0089)
- **IMPLEMENTATION** policy.ts에 categories 필드/검증/DEFAULT_CATEGORY_SUGGESTIONS 상수/readCategoriesStatus/setCategories 추가. store.ts에 ensureColumn으로 decisions.category TEXT 컬럼 마이그레이션. decision.ts/rebuild.ts/source-store.ts에 category 매핑·삽입·검증 반영. categories.ts 신규: listCategoryCounts가 recall과 동일한 가시성 규칙(status IN CONFIRMED/DRAFT, task not ABANDONED)으로 카테고리별/미분류 개수를 집계. cli.ts/commands/v2/index.ts에 sduck categories suggest/set/list 명령 추가. (sources: IMPL-0038)
- **VALIDATION** build/lint 클린, 유닛 170개(신규 v2-categories.test.ts 3개 포함)+e2e 33개 통과. sdcuk-cli 저장소에서 suggest/set/list를 직접 실행해 확인(테스트값은 이후 policy.json 삭제로 원복, 이 저장소는 실제 taxonomy를 아직 채택하지 않음). (sources: EVAL-0020)
