# MEM-0008: sduck categories browse -- 카파시 LLM Wiki식 무순위 전체 목록

## Summary
카테고리(또는 미분류) 안의 결정을 FTS/그래프/RRF 랭킹 없이 id+title만 전부 반환하는 sduck categories browse 명령을 추가했다. listCategoryCounts와 동일한 가시성 규칙(status IN CONFIRMED/DRAFT, task not ABANDONED)을 써서 list에서 본 개수와 browse로 실제 읽는 개수가 항상 일치한다.

## Claims
- **DECISION** categories.ts의 browseCategory(projectRoot, category)가 listCategoryCounts와 동일한 가시성 규칙으로 지정 카테고리(category=null이면 미분류)의 결정을 id+title만, 랭킹 없이 created_at 오름차순으로 전부 반환한다. 카테고리 이름이 설정된 taxonomy에 없으면 CATEGORY_NOT_FOUND로 거부한다. 500개 상한을 두되 초과 시 truncated: true로 정직하게 표시한다(조용히 자르지 않음). (sources: DEC-0090)
- **DECISION** sduck categories browse <category> [--uncategorized] [--json] 명령을 categories 하위 명령 그룹에 추가했다. 결과 렌더링은 recall의 '(DRAFT)' 표시 규칙을 재사용해 CONFIRMED가 아닌 항목만 상태를 괄호로 덧붙인다. (sources: DEC-0091)
- **IMPLEMENTATION** categories.ts에 browseCategory/CategoryBrowseView 추가. errors.ts/messages.ts(en/ko)에 CATEGORY_NOT_FOUND 추가. render.ts에 renderCategoryBrowse 추가. commands/v2/index.ts에 runCategoriesBrowseCommand, cli.ts에 categories browse 하위 명령 배선. (sources: IMPL-0039)
- **VALIDATION** build/lint 클린, 유닛 170개(v2-categories.test.ts에 browse 케이스 3건 보강)+e2e 33개 통과. sdcuk-cli에서 존재하지 않는 카테고리 거부와 --uncategorized 실제 목록 출력을 수동으로 확인. 500개 상한/truncated 플래그는 비용 문제로 코드 리뷰로만 검증(자동 테스트 없음) -- 알려진 한계로 기록. (sources: EVAL-0021)
