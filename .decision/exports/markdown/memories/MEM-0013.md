# MEM-0013: 워크트리 간 ID 중복 방지 -- git common-dir 공유 카운터

## Summary
nextSourceEntityId가 로컬 .decision/ 스캔값만으로 다음 번호를 정해서, 같은 베이스에서 갈라진 두 git worktree가 독립적으로 새 결정을 만들면 같은 DEC-/IMPL-/EVAL- 번호를 발급할 수 있었다. 이제 git rev-parse --git-common-dir(모든 worktree가 공유)에 sduck-id-counters.json을 두고 워크스페이스 잠금과 같은 mkdirSync 기반 잠금(workspace-lock.ts에서 withPathLock으로 일반화)으로 보호해, 로컬 스캔값과 공유 카운터 중 큰 쪽+1을 채택한다. git 저장소가 아니면(테스트 임시 디렉터리 등) 조용히 기존 로컬-전용 동작으로 폴백한다.

## Claims
- **DECISION** shared-ids.ts의 reserveSharedId(projectRoot, prefix, localMax)가 git common-dir 아래 sduck-id-counters.json에 prefix별 발급된 최댓값을 기록하고 withPathLock으로 잠근다. nextSourceEntityId(ids, prefix, projectRoot)로 시그니처를 바꿔 이걸 쓴다. 실사용 호출부(13곳+appendSourceEvent 경유 19곳, task.ts/grill.ts/remember.ts까지 포함해 애초 결정문보다 범위가 넓어짐)를 전부 projectRoot를 전달하도록 갱신했다. 아무 곳에서도 안 불리는 죽은 코드 nextEntityId(DB 직접쓰기)는 손대지 않았다. (sources: DEC-0097, DEC-0098)
- **IMPLEMENTATION** workspace-lock.ts에서 withPathLock을 추출, shared-ids.ts 신규, source-store.ts의 nextSourceEntityId/appendSourceEvent 시그니처 변경, 그리고 draft/retrospective/brief/evaluate/memory/question/trace/context/task/grill/remember.ts의 모든 호출부 갱신. tests/unit/v2-worktree-ids.test.ts 신규: 실제 git repo + git worktree add로 두 워크트리를 만들어 ID가 절대 안 겹침을 검증(reserveSharedId를 일부러 no-op으로 바꿔 이 테스트가 실제로 DEC-0002 충돌을 잡아냄을 먼저 확인한 뒤 원복). (sources: IMPL-0045)
- **VALIDATION** build/lint/typecheck/format 클린, 유닛 173개(신규 워크트리 테스트 포함)+e2e 33개 통과. 회귀 테스트가 실제 버그를 잡아냄을 no-op 임시 변경으로 직접 증명. 전체 스위트 1회 실행에서 무관한 테스트가 드물게 실패하는 걸 발견 -- nextSourceEntityId 호출마다 execFileSync로 git 서브프로세스를 새로 띄우던 게 원인이라 진단하고 projectRoot별 gitCommonDir 캐시를 추가(프로세스당 1회만 git 호출). 이후 전체 스위트 3회 연속 통과로 확인. (sources: EVAL-0026)
