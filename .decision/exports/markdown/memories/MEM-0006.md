# MEM-0006: recall이 DRAFT 상태 결정도 찾도록 CONFIRMED 전용 필터 완화

## Summary
recall.ts의 결정 조회(FTS/LIKE/그래프 보강)가 status='CONFIRMED'만 허용하던 것을 status IN ('CONFIRMED','DRAFT')로 완화했다. REJECTED/SUPERSEDED와 ABANDONED 태스크 소속 결정은 계속 제외한다. sduck-recall-bench로 실측한 결과 sdcuk-cli는 변화 없었고(유일한 DRAFT 대상의 태스크가 ABANDONED라 범위 밖) adieum-api는 Hit@5/Hit@10이 28.6%->57.1%로 2배 개선됐다.

## Claims
- **DECISION** recall.ts의 FTS 결정 쿼리, LIKE 결정 쿼리, fetchDecisionsByIds에서 WHERE d.status = 'CONFIRMED'를 WHERE d.status IN ('CONFIRMED','DRAFT')로 완화했다. REJECTED/SUPERSEDED는 계속 제외(SUPERSEDED는 wiki.ts도 이미 '더 이상 유효하지 않음'으로 취급). render.ts의 renderRecallLocalized는 status가 CONFIRMED가 아닐 때만 '(DRAFT)'를 괄호로 덧붙인다. JSON 출력은 Decision 타입에 이미 status 필드가 있어 변경 불필요. (sources: DEC-0085, DEC-0086)
- **CONSTRAINT** 이 완화는 결정(decision)의 status만 다루고, t.status != 'ABANDONED' 태스크 필터는 그대로 유지한다. 즉 태스크 자체가 ABANDONED면 그 안의 DRAFT 결정은 여전히 안 보인다 -- sdcuk-cli 자체의 DEC-0068이 정확히 이 경우라 이번 수정으로도 해결되지 않는다(의도적 범위 제한, 별도 결정 필요). (sources: DEC-0085)
- **IMPLEMENTATION** recall.ts 3곳(FTS 쿼리, LIKE 쿼리, 그래프 전용 보강 조회)의 SQL WHERE 절 수정, render.ts에 상태 표시 1줄 추가. tests/unit/v2-recall.test.ts에 태스크가 confirm 없이 OPEN으로 남은 DRAFT 결정이 recall에 노출되는지 검증하는 케이스 추가. tests/unit/v2-lifecycle.test.ts의 기존 'CONFIRMED만 노출' 단정을 새 계약(CONFIRMED+DRAFT 노출, REJECTED/SUPERSEDED/ABANDONED-태스크는 계속 제외, context.ts는 별도라 안 바뀜)에 맞게 수정. (sources: IMPL-0036)
- **VALIDATION** build/lint 클린, 유닛 167개+e2e 33개 통과. sduck-recall-bench로 코드 스왑 기반 true old-vs-new 비교(같은 데이터 상태): sdcuk-cli는 66.7%/71.4%/0.380-0.381로 완전 동일(DEC-0068의 태스크가 ABANDONED라 범위 밖, 의도된 결과). adieum-api는 Hit@5/Hit@10이 28.6%->57.1%로 2배 개선(2/7->4/7 hit), 그 중 DEC-0116->DEC-0024와 DEC-0134->DEC-0125가 완전 MISS에서 rank 3/2로 해결됨. MRR은 0.308->0.238로 소폭 하락(이미 top10 밖이던 두 건이 DRAFT 후보 유입 경쟁으로 top40 밖까지 밀려 완전 MISS가 됨, rank1 두 건도 rank2/3로 소폭 밀림 -- Hit@5/10엔 영향 없고 MRR만 미세 손해). DEC-0137->DEC-0124는 조건은 맞지만(DRAFT+OPEN 태스크) 키워드 중첩이 약해 여전히 MISS -- DRAFT 문제가 아니라 이전에 발견한 코퍼스 내 밀집 클러스터 문제와 동일 범주로, 이번 수정 범위 밖. (sources: EVAL-0019)
