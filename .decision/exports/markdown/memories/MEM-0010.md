# MEM-0010: sduck categories tag -- 기존 확정 결정에 카테고리 소급 부여

## Summary
categories.ts의 tagDecisionCategories()가 DecisionWorkspace.mutate를 재사용해 기존(이미 CONFIRMED인) 결정의 category 필드만 안전하게 갱신한다. sduck categories tag <id> <category> 단건, 또는 --stdin으로 {assignments:[...]} 일괄 처리를 지원한다. 실제 결정(DEC-0001)에 적용해 git diff로 category/updatedAt만 바뀌고 다른 필드는 전혀 안 바뀜을 확인했다.

## Claims
- **DECISION** tagDecisionCategories(projectRoot, assignments)가 DecisionWorkspace.mutate로 bundle.decisions를 map해 대상 id의 category와 updatedAt만 바꾼다(다른 필드 불변). category는 설정된 taxonomy 안의 값만 허용, 존재하지 않는 id가 하나라도 있으면 전체가 실패한다(부분 성공 없음) -- mutate가 이미 스테이징+검증+원자적 교체+롤백을 제공하므로 직접 파일을 손대지 않는다. 카테고리는 '무슨 일이 있었다'는 사실 주장이 아니라 조직 메타데이터이므로 원본 필드를 직접 갱신해도 IMPL 트레이스 정정 관행(원본 보존+새 레코드)과 충돌하지 않는다 -- git 히스토리가 감사 기록이 된다. (sources: DEC-0093, DEC-0094)
- **IMPLEMENTATION** categories.ts에 tagDecisionCategories/CategoryAssignment 추가. errors.ts(v2 core)에 DECISION_NOT_FOUND, commands/v2/errors.ts에 TAG_ARGS_REQUIRED 추가. commands/v2/index.ts에 parseTagAssignments+runCategoriesTagCommand. cli.ts에 categories tag [id] [category] --stdin 배선. (sources: IMPL-0041)
- **VALIDATION** build/lint 클린, 유닛 172개(단건 태깅/일괄 태깅/타 필드 불변/전부-아니면-무 실패/잘못된 카테고리 거부 검증 포함)+e2e 33개 통과. sdcuk-cli의 실제 결정 DEC-0001에 적용해 git diff로 category/updatedAt 외 필드가 전혀 안 바뀜을 직접 확인, 테스트 후 원복. (sources: EVAL-0023)
