# MEM-0011: sdcuk-cli 실제 카테고리 체계 확정 + 133개 결정 소급 분류

## Summary
sdcuk-cli의 133개 결정 제목을 전부 훑어 9개 대분류(검색/리콜, 워크플로우 라이프사이클, MCP 계약 설계, 릴리스/배포, 메모리 캡슐, Wiki, 컨텍스트 인덱싱, 로케일/국제화, 테스트/CI/품질)를 확정하고, sduck categories tag --stdin 일괄 태깅으로 133개 전부를 한 번에 분류했다. categories 기능 전체(suggest/set/list/browse/tag)가 실제 프로젝트 규모에서 정상 동작함을 확인했다.

## Claims
- **DECISION** 9개 대분류로 133개 결정 전부를 분류했다: 워크플로우 라이프사이클(32), MCP 계약 설계(31, 대부분 폐기된 0.6 RFC), 검색/리콜(28, FTS5·그래프·RRF·카테고리 기능 자체 포함), 릴리스/배포(15), 메모리 캡슐(8), Wiki(7), 컨텍스트 인덱싱(5), 로케일/국제화(4), 테스트/CI/품질(3). confidence 0.85로 기록 -- 제목만 보고 내린 대량 분류라 경계선 판단에 이견 여지가 있음을 인정. (sources: DEC-0095)
- **VALIDATION** categories list 집계가 처음엔 133과 안 맞아 보였으나(116만 표시), 원인을 직접 조사해 나머지 17개가 전부 ABANDONED 태스크 소속 결정이라 recall과 동일한 가시성 규칙으로 정확히 숨겨진 것임을 확인함(버그 아님, 설계대로 동작). git diff 샘플링으로 category/updated_at 외 필드가 전혀 안 바뀌었음을 확인. 유닛 172개+e2e 33개 통과. 참고로 .decision/exports/markdown/**은 git-diff.ts의 isImplementationPath에서 명시적으로 제외되므로, 이 작업처럼 소스 코드를 안 바꾸는 순수 데이터 작업은 sduck trace에 파일이 안 잡히는 게 정상(버그 아님, 의도된 설계). (sources: EVAL-0024)
