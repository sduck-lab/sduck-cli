# MEM-0002: Memory Capsule retrieval and recovery hardening

## Summary
Memory retrieval now folds only capsule-cited raw records, stale or orphaned capsules cannot block canonical work, canonical Markdown round-trips embedded source-fence prose, automatic context reflects current candidates, and backfill, digest, search, and Korean presentation contracts are explicit and portable.

## Claims
- **DECISION** Matching capsules suppress only raw Decision and Trace IDs they cite; uncited records from the same task remain visible. (sources: DEC-MEMORY-CITED-SOURCE-SUPPRESSION)
- **DECISION** Invalid capsule cross-references are degraded derived state: retrieval omits them and doctor can quarantine only the capsule while canonical history remains usable. (sources: DEC-MEMORY-DEGRADED-READ-RECOVERY)
- **CONSTRAINT** The final sduck-source fence is canonical and every staged source bundle must round-trip before commit. (sources: DEC-SOURCE-CANONICAL-LAST-BLOCK)
- **IMPLEMENTATION** The implementation refreshes automatic context from current candidates, requires explicit historical backfill, uses portable digest ordering and literal multilingual search, and localizes human-readable memory reasons. (sources: IMPL-0027, DEC-CONTEXT-CURRENT-CANDIDATE-SNAPSHOT, DEC-MEMORY-EXPLICIT-BACKFILL, DEC-MEMORY-PORTABLE-SEARCH-LOCALE)
- **VALIDATION** All 160 unit tests and 33 E2E tests passed together with lint, typecheck, format, build, and package dry-run checks. (sources: EVAL-0010, IMPL-0027)
