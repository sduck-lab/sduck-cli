# DEC-0085: recall.ts의 decisions 조회(FTS/LIKE/그래프 보강 조회)에서 status 필터를 CONFIRMED 전용에서 CONFIRMED와 DRAFT를 모두 포함하도록 완화한다

## Decision
sduck-recall-bench로 sdcuk-cli(19쌍 중 2쌍)와 adieum-api(7쌍 중 3쌍, 43%)를 직접 측정한 결과, gold 결정이 DRAFT 상태라서 recall의 CONFIRMED 전용 필터에 걸려 알고리즘과 무관하게 영구히 못 찾는 경우가 실측된 실패 원인 중 가장 큰 비중이었다. REJECTED/SUPERSEDED는 계속 제외한다(SUPERSEDED는 wiki.ts에서도 이미 '더 이상 유효하지 않음'으로 취급하는 상태이고, REJECTED는 명시적으로 폐기된 결정이라 둘 다 노출하면 오도할 수 있다). DRAFT는 그와 달리 아직 확정 안 됐을 뿐 폐기된 게 아니고, 실제 두 저장소 모두에서 다른 결정이 실제로 인용하는 살아있는 이력이었다.

## Rationale
- sduck-recall-bench --verbose로 adieum-api의 DEC-0116->DEC-0024, DEC-0134->DEC-0125, DEC-0137->DEC-0124 3쌍을 직접 열어 gold 결정의 status가 전부 DRAFT임을 확인함
- 같은 패턴이 sdcuk-cli 자체에서도 재현됨: 이번 세션에서 만든 DEC-0082/DEC-0083이 DRAFT 상태인 DEC-0068을 인용해 영구 MISS가 됨
- graph_nodes/graph_edges는 애초에 결정 status와 무관하게 모든 결정을 노드로 저장하므로(rebuild.ts insertGraph), 그래프로 도달 가능한 DRAFT 결정을 recall의 SQL 필터가 뒤늦게 걸러내는 것은 그래프 확장 작업(DEC-0083/0084)의 가치도 깎아먹고 있었음
