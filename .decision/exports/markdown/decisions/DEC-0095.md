# DEC-0095: sdcuk-cli의 대분류 체계를 10개로 정하고 기존 133개 결정 전부를 소급 분류한다

## Decision
133개 결정의 id+title을 전부 훑어 실제 존재하는 클러스터를 확인했다: 검색/리콜(FTS5·그래프·RRF·카테고리 기능 자체 포함, ~28개), 워크플로우 라이프사이클(grill-me·brief·confirm·close 게이트·record-depth 등, ~31개), MCP 계약 설계(대부분 폐기된 0.6 RFC 디지스트/엔벨로프 논의, ~31개), 릴리스/배포(~15개), 메모리 캡슐(~8개), Wiki(~8개), 컨텍스트 인덱싱(~5개), 로케일/국제화(~4개), 테스트/CI/품질(~3개). categories.suggest의 범용 기초 제안 대신 이 프로젝트 실제 이력에 맞춘 10개를 채택했다. sduck categories set으로 확정한 뒤, 133개 전부를 sduck categories tag --stdin 일괄 배정으로 소급 분류한다.

## Rationale
- 사용자가 '이 저장소에 테스트'를 명시적으로 요청함 -- 실제 규모(133개)로 카테고리 인프라가 동작하는지 확인하는 게 목적이므로 실제 이력에 맞는 분류가 필요함
- MCP 계약 설계(~31개)와 워크플로우 라이프사이클(~31개)이 가장 큰 두 덩어리인 건 이 프로젝트가 실제로 0.6 MCP RFC 단계를 거쳤다가 CLI-first로 회귀한 역사를 그대로 반영한 것 -- 분류가 균등하지 않은 건 실제 이력의 정직한 반영이지 결함이 아님
- confidence를 0.85로 낮게 잡은 이유: 다수 결정(133개)에 대한 카테고리 배정은 제목만 보고 내린 판단이라 개별 항목의 경계선 판단(예: DEC-0071을 검색/리콜 vs 메모리 캡슐 중 어디에 넣을지)에는 이견 여지가 있음을 인정함
