# DEC-0093: DecisionWorkspace.mutate로 기존 결정의 category 필드만 갱신하는 tagDecisionCategories()를 추가한다

## Decision
categories.ts에 tagDecisionCategories(projectRoot, assignments: {id, category}[])를 추가한다. submitDraft와 동일하게 DecisionWorkspace.mutate(({bundle}) => ...)로 bundle.decisions를 map해 대상 id의 category(및 updatedAt)만 바꾸고 나머지 필드는 그대로 둔다 -- 이 클래스가 이미 스테이징+전체검증+원자적 교체+실패시 롤백을 제공하므로 파일을 직접 손대지 않는다. 각 category는 설정된 taxonomy 안의 값인지 submit과 동일하게 검증한다. 존재하지 않는 id는 DECISION_NOT_FOUND로 거부한다(부분 실패 없이 전체 트랜잭션이 실패해야 함 -- mutate가 이미 그렇게 동작함). title/summary/rationale 등 다른 필드는 절대 건드리지 않는다.

## Rationale
- 사용자가 '전체 소급 분류 기능부터 만들기'를 선택함
- 카테고리는 '무슨 일이 있었다'는 사실 주장이 아니라 검색을 위한 조직적 메타데이터이므로, IMPL 트레이스 오류를 새 레코드로 정정하는 기존 관행(원본은 그대로 두고 새 기록 추가)과 달리 원본 필드를 직접 갱신해도 히스토리 왜곡이 아니다 -- git 히스토리 자체가 감사 기록이 됨
- DecisionWorkspace.mutate는 이미 draft.ts의 submitDraft가 쓰는 것과 동일한 검증+원자적 커밋 경로이므로 새로운 저수준 파일 I/O를 만들 필요가 없음
