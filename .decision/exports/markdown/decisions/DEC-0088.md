# DEC-0088: Decision에 category?: string 필드를 추가하고 submit 시 프로젝트 taxonomy 안의 값만 허용한다

## Decision
types/index.ts의 Decision/DraftDecision에 category?: string을 추가한다. decisions 테이블에 ensureColumn으로 category TEXT 컬럼을 추가한다(기존 tasks 테이블 마이그레이션과 동일 패턴, ALTER TABLE 안전 재실행). rebuild.ts의 INSERT문과 decision.ts의 mapDecision에 반영한다. submitDraft에서 draftDecision.category가 있으면 정책의 categories 목록에 있는지 검사하고, 목록에 없거나 프로젝트에 아직 taxonomy가 설정 안 됐으면 DRAFT_CATEGORY_INVALID로 거부한다. category가 없으면(생략) 그냥 미분류로 남긴다 -- 기존 결정과 호환.

## Rationale
- 카테고리가 고정 목록 밖 임의 문자열이 되면 분류가 흩어져 처음부터 이 기능을 만드는 의미가 없어짐 -- submit 시점 강제가 핵심
- category를 선택적으로 두어야 기존 sdcuk-cli/adieum-api의 수백 개 결정, 그리고 아직 taxonomy를 안 정한 프로젝트가 계속 동작함(DEC-0085/0086이 그랬듯 recall의 기존 계약을 안 깨는 것과 같은 원칙)
- source-store.ts의 assertDecision은 이미 알려진 필드만 검사하고 초과 필드를 거부하지 않으므로 category가 sduck-source JSON fence를 통해 그대로 왕복됨을 코드로 확인함
